## 1. 复核方法

- 对照 ESP-IDF v5.5.5 的 Kconfig、I2C panel IO 和存储实现。

## 2. 需要更正的审计结论

### 2.1 Flash 模式没有配置冲突

审计报告将以下组合判断为 QIO 120MHz 未生效：

```text
CONFIG_ESPTOOLPY_FLASHMODE_QIO=y
CONFIG_ESPTOOLPY_FLASHMODE="dio"
CONFIG_ESPTOOLPY_FLASHFREQ_120M=y
CONFIG_ESPTOOLPY_FLASHFREQ="80m"
```

ESP-IDF v5.5.5 的 `$IDF_PATH/components/esptool_py/Kconfig.projbuild` 明确说明：

- QIO/QOUT 固件的引导镜像由烧录工具以 DIO 写入和启动；引导程序初始化后切换到四线模式。
- 目标运行频率为 120MHz 时，镜像头使用芯片启动阶段支持的 80MHz，随后由引导程序进入 120MHz。

因此字符串值 `dio` 和 `80m` 是生成镜像头所需的派生配置，不能据此判断运行期退化。当前配置保持不变。微雪官方示例采用 QIO 80MHz 和 PSRAM 80MHz；本项目的 QIO/PSRAM 120MHz 仍需通过实机温度变化和长期运行验证。

### 2.2 CH422G 数值来自官方位定义

微雪官方 Arduino 示例给出的扩展 IO 位为：

| 位 | 用途 |
|---:|---|
| 1 | GT911 复位 |
| 2 | LCD 背光 |
| 3 | LCD 复位 |
| 4 | SD 卡片选 |
| 5 | USB 选择 |

原代码中的 `0x2C`、`0x2E`、`0x1E`、`0x1A`与官方 ESP-IDF 示例完全一致。审计报告对 bit5 可能控制 LCD 的担忧没有得到官方示例支持。本轮将数值替换为具名位组合并补充约束注释，生成值保持一致。

### 2.3 隐私状态机的两项建议不作为缺陷修改

- `AUTH_FAILED` 在非认证状态下执行锁定属于失败时关闭访问的安全策略，保留原行为。
- 锁定事件重复返回关背光、禁用触摸和清数据动作具有幂等性，也能在前一次硬件写入失败后再次收敛到安全状态，保留原行为。

## 3. 已确认并完成的修改

| 项目 | 处理 |
|---|---|
| 协议负载指针生命周期未说明 | 在头文件中注明解码后的负载指向输入缓冲区 |
| 协议未实现最近 32 个序号去重 | 增加支持乱序和 16 位回绕的滑动窗口，并补重复、过旧和回绕测试 |
| 协议边界测试不足 | 增加空负载、最大负载、缓冲区不足和空指针测试 |
| CH422G 与传统 I2C 路径隐蔽 | 增加具名位、官方序列说明、编译期类型检查和迁移警告 |
| `assert` 可能受构建配置影响 | 显示与触摸注册结果改为始终生效的错误检查 |
| 滑动阈值低于设计值 | 触摸输入设备设置为 120 像素最小滑动距离 |
| 日期写死 | 使用系统时间生成日期和星期；未校时时明确提示 |
| 假时钟与无效天气显示为 0 | 未校时时显示占位符，天气与六小时数据等待联网更新 |
| 预警标题缓存偏小 | 扩大到 96 字节，界面超长时显示省略号 |
| UI 锁约定未写明 | 在公开接口注明调用方必须持有 LVGL 锁 |
| 手势回调切页后继续访问事件 | 在删除当前页面前停止事件冒泡 |
| UI 初始化锁失败会被静默忽略 | 改为强制检查锁结果，失败时输出明确错误并停止启动 |
| 仓库包含本机 EIM 和活动脚本绝对路径 | 本地配置加入忽略规则，仓库改为脱敏示例，并将活动文档与脚本改成通用路径 |

## 4. 已确认但暂不修改

| 项目 | 原因与计划 |
|---|---|
| 状态更新时全页重建 | 属于阶段 A 原型的架构债；需要为各页面建立持久控件引用和局部刷新函数，单独实施并做性能对比 |
| 隐私状态机尚未接入实际动作 | BLE GATT 尚未实现；阶段 B 与触摸禁用、数据清理和背光执行器一起闭环 |
| 联调配置保持常亮 | 晚上仍需检查屏幕和触摸；BLE 隐私闭环完成后再建立独立的生产配置 |
| 传统 I2C 驱动 | 当前 GT911 panel IO 的 v1 路径与其配套；迁移需同时修改两端，留到板级驱动稳定后处理 |
| CH422G 缺少共享影子寄存器 | 接入 microSD 前实现，由 `board` 单独拥有，避免背光、SD 和 USB 互相覆盖 |
| 看门狗关闭、LVGL 日志开启 | 当前属于联调配置；发布配置中开启任务看门狗并降低日志级别 |
| UI 曲线、过期态和错误态 | 对应真实数据源接入阶段，当前模拟数据不足以验证完整刷新策略 |
| CTest 与持续集成 | 主机脚本和编译前检查已经可运行，后续接入仓库自动检查 |

## 5. 没有足够证据支持的修改建议

- NVS 24KB 当前没有容量测量证明不足；待 Wi-Fi、蓝牙绑定和设置键全部确定后再计算。
- 全局关闭 C++ 异常可能影响托管组件，需先取得链接映射和组件要求。
- 预警页面的 34 像素偏移从现有坐标未复现报告所述大空档，保留到实屏检查。
- 未识别的协议标志位和消息类型可以服务向前兼容，传输层暂不拒绝。
