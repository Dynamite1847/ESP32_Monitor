## 总体结论

无崩溃级、无安全级缺陷，代码质量明显高于一般嵌入式初创工程：分层清晰、状态所有权正确、边界检查普遍到位、测试覆盖了核心逻辑。主要问题集中在三类：

1. 与设计文档的差距：局部刷新、序号去重、隐私动作接线均未落地；
2. 实机待验证项：CH422G、触摸、I2C 路径；
3. 若干"正确但极其隐蔽、未来必踩雷"的代码。

## 一、ble_protocol ✅ 质量高

- ✅ CRC-16/CCITT-FALSE 实现正确（测试向量 `"123456789"→0x29B1` 验证通过）；校验顺序（魔数→版本→长度→CRC）合理，严格拒绝多余字节（`ble_protocol.c:94` `input_length != expected_length`）。
- 🟡 `decode` 返回的 `frame->payload` 是指向输入缓冲区的指针（`ble_protocol.c:107`），生命周期未文档化——调用方持有输入缓冲多久，payload 就有效多久。
- 🟡 `flags` / `message_type` 未做位掩码与枚举校验（传输层可接受，协议演进时注意）。
- 🟠 协议规范 §8「保留最近 32 个序号、拒绝重复帧」完全没有实现（代码中无任何序号去重）。这是防重复 `ACTION_TRIGGER` / `SLIDER_UPDATE` 造成 Mac 端重复操作的关键机制，建议在阶段 B（ble_link）落地时优先实现，并补 host 测试。
- 🟡 `encode` 未防御 `frame->payload` 与 `output` 重叠（`memcpy` 重叠属 UB，当前调用方不会触发）。

## 二、privacy ✅ 状态机正确

- ✅ 超时判断使用 `uint32_t` 无符号减法（`privacy_state_machine.c:84`），回绕安全；测试 `test_privacy_heartbeat_wraparound` 数学正确。
- ✅ 动作位掩码设计干净（`desk_privacy_actions_t`），"状态机只出动作、调用方执行"职责分离合理。
- 🟡 AUTH_FAILED 缺少状态守卫（`privacy_state_machine.c:56`），而 AUTH_SUCCEEDED 有（`:47`）。已 ACTIVE 时收到 AUTH_FAILED 会锁屏 + 断开 BLE——fail-closed 可接受，但行为不对称，建议对齐。
- 🟡 已锁定状态下重复收到锁定事件，仍返回整套 `LOCK_ACTIONS`（`:66-71`），调用方会重复执行关背光 I2C 写——加"已在 LOCKED 则返回 NONE"可避免。
- 🟡 HEARTBEAT 在非 ACTIVE 状态被静默忽略（设计如此），联调期建议加日志便于排查。

## 三、app_model ✅ 简洁正确

- ✅ 公共（天气/指数）/ 私有（系统/控制/AI/媒体）数据分离与锁定时清理逻辑正确，`revision` 递增机制合理，测试覆盖了清理后公共数据保留。
- 🟡 `desk_weather_alert_t.title[48]`：CJK 每字 3 字节，48B 只能装约 16 字，官方预警标题可能被截断（可接受，但需在 UI 侧考虑省略号）。
- 🟡 mock 与真实数据源之间无适配层占位——阶段 C/D 建 `network` 组件时补。

## 四、board 🟠 实机验证前最需关注

- ✅ 「I2C 端口号强转句柄」经 IDF 5.5.5 源码核查是**正确**写法，但属于"地雷式代码"：
  - `esp_lcd_i2c_bus_handle_t` 就是 `uint32_t`（`esp_lcd_io_i2c.h:17`），`_Generic` 宏据此分发到 v1 传统驱动路径；
  - v1 驱动**强制要求 `scl_speed_hz == 0`**，非 0 直接返回 `ESP_ERR_INVALID_ARG`（`esp_lcd_panel_io_i2c_v1.c:60`）——`board.c:173` 的 `scl_speed_hz = 0` 是**承重墙**，删掉触摸必挂；
  - 两处均无注释；未来迁移新 I2C 驱动时 `_Generic` 会**静默改走 v2 并传入 NULL 句柄，实机必崩**。建议：加注释 + `_Static_assert` 固定路径。
- 🟠 CH422G 魔数无注释（`board.c:92-98, 210-215`）：`0x2C/0x2E`（触摸复位）与 `0x1E/0x1A`（背光）写同一输出寄存器，背光操作会清掉复位设置的 bit5（`0x2E→0x1E`）。若 bit5 控制其他外设（LCD 复位/使能），亮屏时会误触发——设计文档自己把"CH422G 其他位影响"列为实机验证项，代码应注明每一位功能。
- 🟠 GPIO4（`TOUCH_INTERRUPT_GPIO`）被配置为 OUTPUT 且保持（`board.c:83-95`）。该引脚兼作 GT911 地址选择，当前用法正确，但之后无法复用为触摸中断；touch 配置用轮询（`int_gpio_num = -1`）与之自洽，需注释说明。
- 🟠 使用 legacy I2C 驱动（`i2c_driver_install` / `i2c_master_write_to_device`，IDF 5.x 已弃用）。与 v1 panel io 配套是当前唯一正确组合，但建议规划迁移到 `i2c_master_bus`（迁移时上面的 `_Generic` 陷阱会触发，务必同步改）。
- 🟡 初始化中途失败时 panel/touch 句柄泄漏（`board.c:165-203`）——`app_main` 用 `ESP_ERROR_CHECK` 会 abort，实际影响小。
- 🟡 GPIO0 作 RGB 数据线（strapping pin，`board.c:150`）——板级设计，烧录验证时注意 boot 行为。
- 🟡 pclk 16MHz → 约 39fps；桌面时钟够用，切页动画流畅度需实机确认。

## 五、ui 🟠 与设计目标差距最大

- ✅ 全部静态创建、无泄漏路径、所有 `snprintf` 有界、所用字体均已在 sdkconfig 启用（14/16/18/20/24/32/48 + 思源黑体 16）。
- ✅ 滑动切页经 LVGL 9.5.0 源码实证**能工作**：`lv_indev_search_obj` 不做 `CLICKABLE` 过滤，空白区域命中 `content_area`；单指滑动检测 `indev_gesture()` 无条件编译（`lv_indev.c:1773`），`LV_USE_GESTURE_RECOGNITION` 关闭只影响多指手势，与当前无关。
- 🟠 全页重建：`desk_ui_apply_state → render_page → lv_obj_clean(root_screen)`（`ui.c:501-578`），每次数据更新整页重建。系统页 2 秒一次更新会整页闪烁 + 内存抖动。技术架构 §5 明确要求"曲线局部刷新、控制条只在变化时重建"——当前是阶段 A 骨架的合理妥协，但**应在阶段 E/F 前改为局部刷新**，这是与设计文档最大的架构差距。
- 🟡 手势阈值未按文档调优：LVGL 默认 `gesture_min_distance = 50px`（`lv_indev.c:46`），文档要求"15% 屏宽或速度阈值"（≈120px）。建议 `lv_indev_set_gesture_min_distance` 按文档配置，降低误触。
- 🟡 预警条布局不一致（`ui.c:139-196`）：有预警时时钟/温度下移 34px，但分隔线（y=254）和小时天气行（y=276）不随动，产生约 88px 视觉空档，与"上半区缩短、小时天气保持完整"的意图不符。
- 🟡 假时钟逻辑（`ui.c:99-110`，year<2025 分支）与硬编码日期"8月16日 星期日"（`:149`）不一致——bring-up 可接受，接网后应消除。
- 🟡 `desk_ui_apply_state` 依赖调用方持有 LVGL 锁，无文档化约定（`app_main.c:57-60` 的 init 路径做了，但接口层面没写）。
- 🟡 `weather.valid == false` 时仍渲染"未知 0°"——文档 §2.6 要求显示"更新于 xx:xx"的过期态，当前未实现。

## 六、app_main 🟠

- ✅ 启动流程清晰：profile → mock → privacy → 显示 → adapter → UI → 背光。
- 🟠 privacy 状态机是死代码：初始化后从未 `dispatch` / `poll`（`app_main.c:20-22`），返回的动作（背光/触摸/清数据）无处执行；触摸也没有禁用 API，锁定时触摸仍可用。这是阶段 B BLE link 未接入前的自然状态，但应写明 TODO。
- 🟠 `CONFIG_DESK_BRINGUP_DISPLAY_ON=y` 已固化在本地 sdkconfig（Kconfig 默认即 `y`，`components/board/Kconfig`）：当前构建**不带认证常亮**，与"隐私优先"的产品定位相悖。联调期可接受，但生产构建必须显式关闭（`# CONFIG_DESK_BRINGUP_DISPLAY_ON is not set` 写入 sdkconfig.defaults），避免误烧。
- 🟡 `assert(display != NULL)`（`app_main.c:47,52`）在 `NDEBUG` 下被编译掉 → NULL 解引用风险，建议改 `ESP_ERROR_CHECK` 风格。
- 🟡 背光/触摸动作与隐私状态的接线（`desk_privacy_actions_t` 的执行器）完全没有，是阶段 B 的核心工作。

## 七、测试 ✅ 良好基础，有明确缺口

- ✅ 覆盖隐私全路径/回绕、协议编解码、帧篡改、私有数据清理；回绕测试数学正确（`UINT32_MAX-4000` 起跳，poll(2001) 恰好超时）。

## 八、构建与配置 🟡

- ✅ 分区表 16MB 精确铺满：双 OTA 5MB + storage 5.9MB，无浪费。
- 🔴 本地 sdkconfig 存在配置自相矛盾：`CONFIG_ESPTOOLPY_FLASHMODE_QIO=y` 已勾选，但生效值 `CONFIG_ESPTOOLPY_FLASHMODE="dio"`、`CONFIG_ESPTOOLPY_FLASHFREQ="80m"`——**实际构建的是 DIO 80MHz，不是 defaults 声明的 QIO 120MHz**（esptool 烧录提示 `--flash_mode dout --flash_freq 80m` 也证实）。QIO 120M 理论吞吐约为 DIO 80M 的 3 倍，直接影响 LVGL 读字体/资源性能。建议：删除本地 `sdkconfig` 重新生成，或用 menuconfig 明确选定 QIO 120M（同时确认板载 flash 四线已接）。`sdkconfig` 已不入库，fresh clone 不受影响。
- 🟡 `CONFIG_COMPILER_CXX_EXCEPTIONS=y`——纯 C 工程不需要，徒增体积；`CONFIG_ESP_TASK_WDT_EN=n` 生产应开启；`CONFIG_LV_USE_LOG=y` 生产应关。
- 🟡 `-Wno-attributes`（`firmware/CMakeLists.txt:4`）全局压制告警，建议收窄到具体组件。
- 🟡 nvs 分区 24KB（`partitions.csv`）：Wi-Fi 凭据 + BLE 共享密钥 + 设置会偏紧，建议 32KB。
